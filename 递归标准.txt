SOS_Workbench 0.1.0 递归调用标准

实例文件：skills/phase3/chat_bot.py            子任务技能（含阻塞/唤醒实现）
平台实现：phases/phase2.py                     Phase2Freedom._run_skill（嵌套调用与阻塞）
          phases/phase3.py                     会话、聊天日志、终止标记
          ui/phase3_task_panel.py              人工终止入口（发送「杀死」）

修订说明：1.0 取代旧版《套娃标准》，术语、契约、状态机与校验项全部重写。
          文中"必须/禁止"为强制项；"建议"为实现参考。


======================================================================
0. 适用范围
======================================================================
本文件规定**同一进程内**的父子任务嵌套：
    L2 任务（步骤链）在执行某一步时调用 L3 技能，并把该步骤挂起，
    直到人工或模型显式结束子任务，父任务再继续执行后续步骤。

不涉及：跨进程、跨机器、分布式编排、持久化中断恢复。
这些能力如需引入，应先修订本标准的 §3、§5、§9。


======================================================================
1. 术语与层级
======================================================================
父任务 parent    二级编排任务（Freedom 任务），持有 task_name / task_id / 当前轮次
子技能 child     继承 BaseSkill 且 category == "phase3" 的技能实例
调用深度 d       父任务为 1，其直接子任务为 2；平台当前只允许 d ≤ 2
嵌套键 nest_key  一次父子配对的唯一标识，用于事件与结果的隔离
挂起 suspend     父任务阻塞等待子任务结束的状态
唤醒 wakeup      子任务结束，父任务恢复执行

层级与深度：

    d=1  L2 任务（父）
          └── d=2  L3 技能（子，blocking_mode=True）

平台当前不支持 d ≥ 3。子技能内部不得再嵌套另一个 L3 技能（见 §9）。


======================================================================
2. 递归契约
======================================================================
2.1 触发条件（三者同时满足）
    · 步骤 type == "skill"
    · 技能所属模块路径包含 "phase3"
    · 步骤 params 中存在 "phase3_task" 字段

2.2 平台强制注入的参数
    参数名            含义
    app               主应用实例
    host              父任务的目标（只读）
    task_name         "phase3_task" 的值，即子面板名，同时作为 nest_key
    blocking_mode     True
    log_fn            输出到父任务日志的函数

2.3 返回值语义
    子技能的返回值被转为字符串，作为该步骤的 result["output"]。
    返回值应为**可读摘要**，不是全量数据；建议 ≤ 2000 字符。
    全量数据应落在子任务自己的 chat_log.json，由人查看。

2.4 允许与禁止

    操作                                      允许  说明
    ----------------------------------------  ----  ------------------------------
    读取 host / 父轮次                         允许  只读
    写子面板自己的聊天日志                      允许  phase3_manager.append_chat_log
    请求模型                                   允许  app.chat_client.send
    读取父任务轮次摘要                          允许  phase3_manager.get_round_summary_text
    通过 kill 的 result 回传结果                允许  唯一上行通道
    修改父任务的步骤链                          禁止  必须走平台 API，不要直接改控件
    写父任务的日志缓冲 / 控件                   禁止  只能经 log_fn
    再嵌套一个 L3 技能                          禁止  深度上限 d ≤ 2
    使用全局可变状态跨父子共享                  禁止  见 §4


======================================================================
3. 生命周期状态机
======================================================================
    [IDLE]
      │ execute(blocking_mode=True)
      ▼
    [SUSPENDED]  登记 nest_key → event，阻塞等待
      │ event.set()（kill_blocking_task / 超时）
      ▼
    [WAKEUP]     取出 result，清理 nest_key
      │
      ▼
    [TERMINATED] 返回 result 字符串，父任务继续

强制要求：
    R1  进入 SUSPENDED 之前必须登记 event，且 nest_key 唯一
    R2  退出时必须清理登记（无论正常唤醒、超时还是异常）
    R3  唤醒后只能读取一次结果，第二次读取必须返回空
    R4  任何路径都不得让父任务永久阻塞（必须有上限，见 §5）


======================================================================
4. 数据流与隔离
======================================================================
4.1 下行（父 → 子）
    host、task_name、以及父任务当前轮次（如需）。除此之外不传递。
    子技能不得依赖父任务的内存对象（app.targets、panel.tool_boxes 等）。

4.2 上行（子 → 父）
    仅通过 kill_blocking_task(nest_key, result) 的 result 参数。
    result 建议为 JSON 字符串（例如子任务的 chat_log 摘要），由父任务按需解析。

4.3 状态隔离
    · 闭包/事件/结果字典按 nest_key 分区，禁止使用单个实例级变量
    · 禁止跨父子共享可变容器
    · 子技能不得修改父技能的 _log_buffer、current_host、start_time


======================================================================
5. 终止条件与超时
======================================================================
5.1 正常终止
    用户在子面板发送「杀死 / 自杀 / 终止」
    → ui/phase3_task_panel.py 调用 skill.kill_blocking_task(nest_key, payload)
    → 父任务恢复

5.2 模型终止
    子技能调用 phase3_manager.request_death(task_name)，再自行结束并唤醒父任务。

5.3 超时（强制）
    父任务的等待必须有上限。示例实现默认 3600 秒。
    超时后：清理登记、返回 "无结果（等待超时）"、父任务继续执行（标记该步 success=False 由父级决定）。

5.4 异常终止
    子技能抛异常 → 父步骤 result["success"] = False，链继续（不中断整轮）。
    异常必须写日志，不得静默吞掉。

5.5 平台级终止（当前缺口）
    L2 任务的「杀死」目前不会唤醒嵌套中的子任务，见 §9-G1。
    在该缺口修复前，操作顺序必须是：先结束子任务，再杀父任务。


======================================================================
6. 并发与单例约束
======================================================================
    平台对每个技能类只创建一个实例（热插拔加载时实例化一次）。
    因此 _block_events / _block_results 是**实例级**的，必须按 nest_key 分区。

    强制：nest_key 必须能区分不同父任务。
    建议：nest_key = f"{parent_task_id}::{child_task_name}"

    当前平台传入的 task_name 只是子面板名；两个父任务嵌套同一子面板会串线。
    在该缺口修复前，禁止两个 L2 任务同时嵌套同一个 L3 面板。


======================================================================
7. 可观测性
======================================================================
    每个嵌套周期必须产生三条日志（前缀沿用历史命名 [套娃]）：
        [套娃] 已挂起，等待子面板 [<nest_key>] 结束
        [套娃] 已唤醒，结果长度 <n>
        [套娃] 等待超时

    建议同时写入结构化日志（structured_logger）：
        event = nested_start / nested_wakeup / nested_end
        字段   parent、child、depth、duration、reason(manual|timeout|death|exception)

    父任务的轮次汇总只记录子任务的返回值摘要，不记录子任务的全量日志。


======================================================================
8. 失败语义
======================================================================
    情形                     父任务表现                        子任务
    -----------------------  --------------------------------  ----------------
    子技能返回正常字符串       该步 success=True                正常结束
    子技能主动 die            该步 success=True，output 说明    标记死亡
    子技能异常                该步 success=False，链继续        记录异常
    等待超时                  该步 success=False，链继续        可能仍在运行
    父任务被强杀               见 §9-G1                         事件未释放

    原则：子任务的失败不得导致整条链崩溃；父任务必须能继续执行下一步。

10. 实现模板（真实示例）
======================================================================
实例文件：skills/phase3/chat_bot.py

    import threading
    from core.skill.base_skill import BaseSkill

    class ChatBotSkill(BaseSkill):
        name = "chat_bot"
        description = "三级示例技能：同步调用模型并记录对话，支持被父任务嵌套调用"
        category = "phase3"

        BLOCK_TIMEOUT = 3600

        def __init__(self, toolbox):
            super().__init__(toolbox)
            self._block_events = {}
            self._block_results = {}

        def execute(self, **kwargs):
            if kwargs.get("blocking_mode"):
                return self._execute_blocking(
                    kwargs.get("app"),
                    kwargs.get("host", ""),
                    kwargs.get("task_name", ""),
                    kwargs.get("log_fn", lambda m: None),
                )
            # 非阻塞模式：正常业务（见文件本体）
            ...

        def _execute_blocking(self, app, host, caller_task_name, log_fn):
            event = threading.Event()
            self._block_events[caller_task_name] = event
            log_fn(f"[套娃] 已挂起，等待子面板 [{caller_task_name}] 结束")
            finished = event.wait(self.BLOCK_TIMEOUT)
            self._block_events.pop(caller_task_name, None)
            result = self._block_results.pop(caller_task_name, "无结果")
            if not finished:
                log_fn("[套娃] 等待超时")
                return "无结果（等待超时）"
            log_fn(f"[套娃] 已唤醒，结果长度 {len(str(result))}")
            return result

        def kill_blocking_task(self, task_name, result=""):
            event = self._block_events.get(task_name)
            if not event:
                return False
            self._block_results[task_name] = result
            event.set()
            return True

11. 自检清单
======================================================================
    □ category 为 "phase3"，否则不会被当作子任务技能
    □ execute() 检测 blocking_mode，并转交 _execute_blocking
    □ 进入阻塞前已登记 event，且 nest_key 唯一
    □ 退出路径（正常/超时/异常）都会清理登记
    □ 等待有上限（BLOCK_TIMEOUT），不会永久阻塞
    □ 实现 kill_blocking_task，且只唤醒一次
    □ 上行结果只经 result 参数，长度 ≤ 2000 字符
    □ 不修改父任务的日志缓冲与控件
    □ 不嵌套第二层（d ≤ 2）
    □ 三条关键日志齐全（挂起 / 唤醒 / 超时）
    □ 异常写日志，不静默
